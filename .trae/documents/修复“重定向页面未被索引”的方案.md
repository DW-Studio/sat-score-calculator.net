## 问题归因
- 站点存在 URL 变体（www 与非 www、http 与 https、带/不带尾斜杠、根路径与 /index.html），搜索引擎会将重定向目标视为规范版本，仅索引最终 200 页面，而将中间 3xx 页面标记为“重定向页面，未被索引”。
- sitemap/页面内链接/canonical/OG/Twitter 等若引用了非最终规范 URL，会被 Search Console 标记为重定向来源。

## 修复策略
- 统一规范域：选定一个规范主域（建议 `https://www.sat-score-calculator.net/` 或实际无重定向的版本），其余全部 301 到规范主域。
- 保证所有可爬资源只暴露规范 URL：
  - 页面 `<link rel="canonical">`、`hreflang` 指向规范主域
  - sitemap.xml 仅包含规范 URL（不包含任何 3xx）
  - robots.txt 的 Sitemap 指向规范 URL
  - 站内绝对链接、OG/Twitter 的 `og:url` 与 `og:image` 均使用规范 URL
- 清理易触发重定向的引用：
  - 不使用 `/index.html`（改为根 `/`）
  - 统一尾斜杠策略（与服务端一致）；sitemap 与 canonical 保持同一形式

## 代码与配置调整（仓库内）
- 检查并对齐三处：
  - index.html 头部的 canonical/hreflang/OG/Twitter 使用规范域
  - sitemap.xml 的 `<loc>` 使用规范域
  - robots.txt 的 Sitemap 使用规范域
- 可选增强：添加 `<link rel="alternate" hreflang="x-default" href="[规范域]">`，减少国际化歧义。

## 服务端配置（仓库外）
- 设置 301 永久重定向：
  - 非 www → www 或反之（与选择的规范一致）
  - http → https
  - `/index.html` → `/`
  - 统一尾斜杠策略（例如全部无尾斜杠）

## 验证流程
- 用 Search Console 的 URL 检查工具测试：根路径与 sitemap 中 URL 返回 200 且“可编入索引”。
- 以 curl 或浏览器检查变体：确认全部返回 301 到规范主域，不存在多级重定向链。
- 重新提交 sitemap 并触发抓取；观察 Coverage 报告中的“重定向页面”数量下降。
